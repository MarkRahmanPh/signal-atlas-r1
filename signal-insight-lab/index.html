What makes this different?

Instead of only displaying events, this workspace tests data completeness, reconstructs bounded intervals, highlights possible short greens and detector chatter, and gives a transparent scenario comparison.

Recommendations are review prompts, not automatic controller changes. True split failure, delay, arrivals on green, and volume require validated detector and phase mapping plus appropriate detection placement.

Planned: phase sequence anomalies, max-out screening, detector-to-phase assignment, Purdue Coordination Diagrams, and comparative operational studies.

What this tool measures—and what it cannot yet measure

Available from event logs

Observed phase green service intervals; frequency of gap-out, max-out and force-off codes; pedestrian event-code counts; detector ON/OFF actuation counts; event timeline; incomplete pair and data-quality screens.

Needs validated configuration

Phase assignments, detector roles, direction, stop bar vs advanced detector, overlap configuration, permissive FYA logic, coordinated phases, cycle reference point, split settings, controller model/firmware, event code dictionary.

Needs more inputs or modeling

HCM delay, queue length, capacity, true split failure, red-light violation inference, reliable approach volumes, arrivals on green, offset optimization, multimodal travel time, preemption and TSP response quality.

Privacy and security

Uploads are analyzed inside your browser. SQLite parsing uses sql.js downloaded from a CDN. Do not commit operational controller logs, passwords, or nonpublic intersection configuration to a publicly accessible GitHub repository.
